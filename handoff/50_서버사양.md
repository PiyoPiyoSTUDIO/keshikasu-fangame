# 50. 서버 사양 (Supabase)

- **문서 버전**: v1.0
- **최종 수정**: 2026-06-24
- **범위**: Phase 1 랭킹 + 클라우드 세이브. 모두 무료 티어 내에서 구성.

---

## 1. 목적
- **랭킹**: 최고점 상위 N명 조회
- **클라우드 세이브**: 자기 최고점을 익명 계정에 백업(기기 바꿔도 복구 여지)
- **비용**: 0원 유지. 유료 전환 트리거를 §9에 명시.

## 2. 무료 한도 (2026-06 기준, Supabase 공식 가격 페이지)
| 항목 | 무료 한도 |
|---|---|
| DB 용량 | 500 MB |
| 파일 저장 | 1 GB |
| DB 송신(egress) | 5 GB / 월 |
| 월 활성 사용자(MAU) | 50,000 |
| 활성 프로젝트 | 계정당 2개 (일시정지는 미포함) |
| 자동 정지 | 7일 미사용 시 (수동 재개, 데이터 보존) |
| 자동 백업 | 없음 (무료) |

> 본 게임은 최고점 1행/사용자 + 랭킹 조회뿐이라 위 한도를 매우 여유 있게 사용. 송신(egress)만 주의.

## 3. 구성
- 조직: `Piyopiyo Studio` (Free)
- 프로젝트: `keshikasu-fangame`
- 리전: `Northeast Asia (Tokyo)`
- 환경변수: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (둘 다 공개 가능 — RLS 전제)

## 4. 인증 (익명 로그인) — 방식 (가) 확정
- **로그인 화면 없음.** 첫 실행 시 백그라운드로 **익명 세션** 자동 생성 → 기기에 저장 → 자동 복원. 사용자 체감은 "무로그인"과 동일.
- 익명 사용자도 `auth.users`에 행이 생기고 `auth.uid()`로 식별 → **기기당 1행**(중복 랭킹 방지) + 본인 데이터만 쓰기.
- 가짜 점수 스팸은 RLS로 일부 차단(완벽 방어 아님 — 서버검증은 차후).
- 주의: 익명 인증 시 MAU에 1명 집계(5만 한도라 여유).

## 5. 데이터 모델 — scores 테이블
```sql
-- ランキング用スコアテーブル（1ユーザー1行）
create table public.scores (
  user_id uuid primary key references auth.users (id), -- 匿名ユーザーID（主キー）
  name text not null default 'ゲスト',                  -- 表示名
  best integer not null default 0,                     -- 自己ベストスコア
  updated_at timestamptz not null default now()        -- 更新日時
);

-- ベストスコア降順の取得を高速化するインデックス
create index scores_best_idx on public.scores (best desc);
```

## 6. RLS (행 단위 보안)
```sql
-- 行レベルセキュリティを有効化
alter table public.scores enable row level security;

-- ランキングは全員が閲覧可能
create policy "scores_select_all"
  on public.scores for select
  using (true);

-- 自分の行だけ追加できる
create policy "scores_insert_own"
  on public.scores for insert
  with check (auth.uid() = user_id);

-- 自分の行だけ更新できる
create policy "scores_update_own"
  on public.scores for update
  using (auth.uid() = user_id);
```

> 핵심: 공개 anon 키가 노출돼도 RLS가 "남의 행 쓰기"를 막는다. 단, **service_role 키는 절대 클라이언트에 넣지 않는다.**

## 7. 클라이언트 연동 (supabase-js)
```typescript
import { createClient } from '@supabase/supabase-js';

// URLと公開キーを環境変数から読み込む（公開キーはRLS前提で安全）
const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY,
);

// 匿名ログイン（セッションが無ければ作成）
export async function ensureAnonSignIn() {
  const { data } = await supabase.auth.getSession();
  if (!data.session) {
    await supabase.auth.signInAnonymously();
  }
}

// 自己ベストを保存（1ユーザー1行をupsert）
export async function saveBest(name: string, best: number) {
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return; // オフライン等は黙ってスキップ
  await supabase.from('scores').upsert(
    {
      user_id: user.id,                  // 自分の行を一意に特定
      name,
      best,
      updated_at: new Date().toISOString(),
    },
    { onConflict: 'user_id' },
  );
}

// ランキング上位を取得
export async function fetchTop(limit = 50) {
  const { data } = await supabase
    .from('scores')
    .select('name, best')
    .order('best', { ascending: false })
    .limit(limit);
  return data ?? [];
}
```

> 모든 서버 호출은 try/catch로 감싸 실패해도 게임 진행을 막지 않는다(오프라인 우선 설계).

## 7.1 랭킹 갱신 흐름 (only-if-best)
서버 전송은 **로컬 최고점 갱신 시에만**. 매 판 보내지 않아 egress를 아낀다.
```typescript
// ゲームオーバー時に呼ぶ。ローカル自己ベストを更新した時だけサーバーへ送る
export async function onGameOver(finalScore: number) {
  const localBest = loadLocalBest();        // localStorageの自己ベスト
  if (finalScore <= localBest) return;      // 更新でなければ何もしない（送信もしない）

  saveLocalBest(finalScore);                // まずローカルに保存（オフライン保証）

  const name = ensureName();                // 初回のみ入力→localStorage記憶
  try {
    await ensureAnonSignIn();               // 背景で匿名セッション確保
    await saveBest(name, finalScore);       // 自分の1行をupsert
  } catch {
    // オフライン等は黙ってスキップ。次回更新時に再送される
  }
}
```

## 7.2 이름 입력 (표시명)
- **최초 1회만** 입력(랭킹에 처음 오를 때) → `localStorage`(`playerName`)에 기억 → 이후 자동 사용.
- 설정 화면에서 변경 가능(변경 시 다음 갱신부터 반영).
- 미입력 기본값 `'ゲスト'`(로케일별 기본명은 `25`와 연계 가능).
```typescript
// 表示名を確保する。無ければ初回入力させてlocalStorageに保存
export function ensureName(): string {
  const saved = localStorage.getItem('playerName');
  if (saved) return saved;
  const input = promptForName();            // 初回のみUIで入力（実装はTitle/Result側）
  localStorage.setItem('playerName', input);
  return input;
}
```

## 8. 키프얼라이브 (7일 자동정지 방지)
GitHub Actions로 3일마다 가벼운 요청을 보내 프로젝트를 깨운다. 무료.
```yaml
# Supabaseの7日間自動停止を防ぐ定期ping
name: keepalive
on:
  schedule:
    - cron: '0 0 */3 * *'   # 3日ごとに実行
  workflow_dispatch:         # 手動実行も可能
jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - name: ping supabase rest
        run: |
          # スコアテーブルに軽いクエリを送りアクティブ状態を維持
          curl -s "$SUPABASE_URL/rest/v1/scores?select=best&limit=1" \
            -H "apikey: $SUPABASE_ANON_KEY" > /dev/null
        env:
          SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
          SUPABASE_ANON_KEY: ${{ secrets.SUPABASE_ANON_KEY }}
```
> GitHub 저장소 Secrets에 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 등록 필요.

## 9. 유료 전환 트리거 (이때만 Pro 검토)
- 활성 프로젝트 3개째가 필요할 때
- DB 500MB / egress 5GB(월) 초과가 보일 때
- 자동 백업 · SLA가 필요해질 때(실서비스화)
- MAU 5만 초과(사실상 흥행 신호)

> Phase 1~3 팬게임 규모에선 도달 가능성 낮음. 도달 시점에 재평가.
