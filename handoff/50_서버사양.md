# 50. 서버 사양 (Supabase)

- **문서 버전**: v1.1
- **최종 수정**: 2026-06-25
- **범위**: Phase 1 랭킹 + 클라우드 세이브. 모두 무료 티어 내에서 구성.

---

## 1. 목적
- **랭킹**: 최고점 상위 N명 조회
- **클라우드 세이브**: 자기 최고점을 익명 계정에 백업(기기 바꿔도 복구 여지)
- **비용**: 0원 유지. 유료 전환 트리거를 §9에 명시.

## 2. 무료 한도 (2026-06 기준, Supabase 공식 가격 페이지)
| 항목 | 무료 한도 |
|---|---|
| DB 용량 | 500 MB |
| 파일 저장 | 1 GB |
| DB 송신(egress) | 5 GB / 월 |
| 월 활성 사용자(MAU) | 50,000 |
| 활성 프로젝트 | 계정당 2개 (일시정지는 미포함) |
| 자동 정지 | 7일 미사용 시 (수동 재개, 데이터 보존) |
| 자동 백업 | 없음 (무료) |

> 본 게임은 최고점 1행/사용자 + 랭킹 조회뿐이라 위 한도를 매우 여유 있게 사용. 송신(egress)만 주의.

- 조직: `Piyopiyo Studio` (Free)

- 리전: `Northeast Asia (Tokyo)`

  - **`VITE_SUPABASE_URL`**: `https://<프로젝트참조>.supabase.co` 까지만. **`/rest/v1` 등 경로는 붙이지 않는다**(supabase-js가 내부에서 붙임).
  - 로컬은 루트 `.env`(gitignore), 배포는 GitHub Secrets(§8·`60`).

> **키 체계 주의 (2026-06 시점)**: Supabase가 키를 개편해 신규 `sb_publishable_...`(클라이언트용)과 레거시 `eyJ...`(anon/public · service_role)가 공존한다. 본 프로젝트는 **레거시 anon(public) `eyJ...`** 를 `VITE_SUPABASE_ANON_KEY`로 사용(문서·코드 전제). 레거시는 2026년 말 폐기 예정이라, 그 전 마이그레이션 시 publishable 키로 교체 가능. **service_role(secret)은 절대 클라이언트/빌드/저장소에 넣지 않는다.**

## 4. 인증 (익명 로그인) — 방식 (가) 확정
- **로그인 화면 없음.** 첫 실행 시 백그라운드로 **익명 세션** 자동 생성 → 기기에 저장 → 자동 복원. 사용자 체감은 "무로그인"과 동일.
- 익명 사용자도 `auth.users`에 행이 생기고 `auth.uid()`로 식별 → **기기당 1행**(중복 랭킹 방지) + 본인 데이터만 쓰기.
- 가짜 점수 스팸은 RLS로 일부 차단(완벽 방어 아님 — 서버검증은 차후).
- 주의: 익명 인증 시 MAU에 1명 집계(5만 한도라 여유).

> **★ 필수 대시보드 설정**: 익명 로그인은 **기본 OFF**다. **Authentication → Sign In / Providers(또는 Configuration)의 "Allow anonymous sign-ins"** 토글을 **ON + Save** 해야 한다. OFF 상태면 `signInAnonymously()`가 **422**로 실패하고, 후속 `scores` upsert도 user 없음으로 스킵된다(증상: 게임은 정상이나 랭킹 row가 안 생김). 저장 후 새로고침해 토글이 ON 유지되는지 확인할 것.

## 5. 데이터 모델 — scores 테이블
```sql
-- ランキング用スコアテーブル（1ユーザー1行）
create table public.scores (
  user_id uuid primary key references auth.users (id), -- 匿名ユーザーID（主キー）
  name text not null default 'ゲスト',                  -- 表示名
  best integer not null default 0,                     -- 自己ベストスコア
  updated_at timestamptz not null default now()        -- 更新日時
);

-- ベストスコア降順の取得を高速化するインデックス
create index scores_best_idx on public.scores (best desc);
```

> 실제 전송되는 표시명은 클라이언트의 `name.default`(현재 ja=`匿名のひよこちゃん`)다. 위 SQL default `'ゲスト'`는 직접 INSERT 시의 폴백일 뿐, 게임 경로에선 항상 클라이언트가 name을 채워 보낸다.

## 6. RLS (행 단위 보안)
```sql
-- 行レベルセキュリティを有効化
alter table public.scores enable row level security;

-- ランキングは全員が閲覧可能
create policy "scores_select_all"
  on public.scores for select
  using (true);

-- 自分の行だけ追加できる
create policy "scores_insert_own"
  on public.scores for insert
  with check (auth.uid() = user_id);

-- 自分の行だけ更新できる
create policy "scores_update_own"
  on public.scores for update
  using (auth.uid() = user_id);
```

> 핵심: 공개 anon 키가 노출돼도 RLS가 "남의 행 쓰기"를 막는다. 단, **service_role 키는 절대 클라이언트에 넣지 않는다.**
> 익명 사용자는 `authenticated` 역할을 쓴다. 본 게임은 전원이 익명이라 영구/익명 구분이 불필요해 위 정책으로 충분(JWT `is_anonymous` 체크 불요). 향후 영구 계정을 도입하면 정책 재검토.

## 7. 클라이언트 연동 (supabase-js) — 실제 구현 기준
> **설계 변경**: `50` 초안의 `onGameOver`(localStorage 비교 포함)는 채택하지 않았다. **로컬 비교는 `services/saveLocal.ts`가 담당**하고, `supabase.ts`는 **전송 책임만** 가진다(책임 분리). GameScene이 둘을 조합한다. 실제 파일은 아래 구조.

```typescript
import { createClient } from '@supabase/supabase-js';

// URLと公開キーを環境変数から読み込む（公開キーはRLS前提で安全）
const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY,
);

// 匿名ログイン（セッションが無ければ作成する）
export async function ensureAnonSignIn(): Promise<void> {
  const { data } = await supabase.auth.getSession();
  if (!data.session) {
    await supabase.auth.signInAnonymously();
  }
}

// 自己ベストを保存する（1ユーザー1行をupsert）。内部関数（外部に公開しない）
async function saveBest(name: string, best: number): Promise<void> {
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return; // セッション未確立時は黙ってスキップ
  await supabase.from('scores').upsert(
    {
      user_id: user.id,                  // 自分の行を一意に特定
      name,
      best,
      updated_at: new Date().toISOString(),
    },
    { onConflict: 'user_id' },
  );
}

// ベスト更新時のみサーバーへ送る（only-if-best判定はGameScene側）。失敗してもゲームは止めない
export async function submitBest(name: string, finalScore: number): Promise<void> {
  try {
    await ensureAnonSignIn();         // 背景で匿名セッション確保
    await saveBest(name, finalScore); // 自分の1行をupsert
  } catch {
    // オフライン・サーバー障害時は黙ってスキップ。次回更新時に再送される
  }
}

// ランキング上位を取得する（表示はタイトル画面④で利用予定）
export async function fetchTop(limit = 50): Promise<{ name: string; best: number }[]> {
  try {
    const { data } = await supabase
      .from('scores')
      .select('name, best')
      .order('best', { ascending: false })
      .limit(limit);
    return data ?? [];
  } catch {
    return []; // 取得失敗時は空配列
  }
}
```

> 모든 서버 호출은 try/catch로 감싸 실패해도 게임 진행을 막지 않는다(오프라인 우선 설계).

## 7.1 랭킹 갱신 흐름 (only-if-best) — GameScene 측
서버 전송은 **로컬 최고점 갱신 시에만**. 매 판 보내지 않아 egress를 아낀다.
**판정 기준은 `loadLocalBest()`(저장된 직전 best)** 다. ★주의: 화면 표시용 `this.best`는 플레이 중 `addScore`에서 실시간 갱신되므로, 게임오버 시점엔 `score === this.best`가 되어 판정에 쓸 수 없다(쓰면 전송이 영영 안 일어난다). 반드시 저장값과 비교한다.

```typescript
// GameScene.gameOver() 内（実装の要点）
const savedBest = loadLocalBest();          // 前回までの保存ベスト
const isNewRecord = this.score > savedBest; // 今回が記録更新か

if (isNewRecord) {
  this.best = this.score;                   // 表示用ベストも揃える
  saveLocalBest(this.best);                 // localStorageへ（オフライン保証）
  void submitBest(t('name.default'), this.best); // 更新時のみ送信（待たない）
}
```

## 7.2 이름 입력 (표시명)
- **현재(③ 시점)**: 전송 표시명은 `t('name.default')` 고정(ja=`匿名のひよこちゃん`). 입력 UI 없음.
- **예정(④ 타이틀)**: **최초 1회만** 입력(랭킹에 처음 오를 때) → `localStorage`(`playerName`)에 기억 → 이후 자동 사용. 미입력 시 `name.default` 폴백. 설정에서 변경 가능(다음 갱신부터 반영).
```typescript
// 表示名を確保する。無ければ初回入力させてlocalStorageに保存（④で実装予定）
export function ensureName(): string {
  const saved = localStorage.getItem('playerName');
  if (saved) return saved;
  const input = promptForName();            // 初回のみUIで入力（実装はTitle/Result側）
  localStorage.setItem('playerName', input);
  return input;
}
```

## 8. 키프얼라이브 (7일 자동정지 방지)
GitHub Actions로 3일마다 가벼운 요청을 보내 프로젝트를 깨운다. 무료.
```yaml
# Supabaseの7日間自動停止を防ぐ定期ping
name: keepalive
on:
  schedule:
    - cron: '0 0 */3 * *'   # 3日ごとに実行
  workflow_dispatch:         # 手動実行も可能
jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - name: ping supabase rest
        run: |
          # スコアテーブルに軽いクエリを送りアクティブ状態を維持
          curl -s "$SUPABASE_URL/rest/v1/scores?select=best&limit=1" \
            -H "apikey: $SUPABASE_ANON_KEY" > /dev/null
        env:
          SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
          SUPABASE_ANON_KEY: ${{ secrets.SUPABASE_ANON_KEY }}
```
> GitHub 저장소 Secrets에 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 등록 필요.
> **현재 미설정 상태**: keepalive 워크플로(`.github/workflows/keepalive.yml`)·Secrets 등록은 아직. 배포 환경에서 랭킹이 실제 동작하려면 deploy.yml 빌드에도 두 env 주입 필요(`60` §5와 공유).
