# 30. 에셋 파이프라인

- **문서 버전**: v1.0
- **최종 수정**: 2026-06-24
- **범위**: 케시카스 정적 일러스트의 입력 규격 · 네이밍 · 동작(모션) 전략 · CJK 폰트 · 최적화.

---

## 1. 목적 / 원칙
- 기존 케시카스 정적 일러스트를 그대로 활용. 동작은 **무료 수단 우선**으로 단계적 적용.
- 규격을 통일해 임포트 · 교체 비용을 최소화.

## 2. 일러스트 입력 규격
| 항목 | 규격 |
|---|---|
| 포맷 | PNG, 투명 배경(RGBA) |
| 단위 | 캐릭터 1종 = 1파일, 주변 여백 트림, 중심 정렬 |
| 해상도 | 캐릭터 장변 약 512px (표시의 약 2배, 레티나 대비) |
| 색공간 | sRGB |
| 글자 포함 | 가능한 한 글자는 이미지에서 제외 → 폰트 렌더(L10N, `25`) |

## 3. 네이밍 규칙
- 캐릭터: `char_<key>` (예: `char_candy`, `char_mammoth`) — `merge_ladder` key와 일치
- UI: `ui_<name>` (예: `ui_button_retry`)
- 글자 박힌 이미지(언어별): `<asset>__<locale>` (예: `logo_title__ko`) — `25` 연계
- 아이콘: `icon-192.png`, `icon-512.png` (PWA, `60`)

## 4. 폴더 구조
```
public/assets/
  characters/   char_*.png
  ui/           ui_*.png, icon-*.png
  fonts/        *.woff2
  logo/         logo_*__<locale>.png
```

## 5. 동작(모션) 전략 — 4계층 (무료 우선) ★핵심
2026년 현재, **AI는 단일 이미지 생성엔 강하지만 한 캐릭터의 일관된 모션 프레임엔 아직 약하다**(프레임 간 디테일 드리프트). 따라서 무료 절차적 애니를 1순위로, AI는 보조로 배치한다.

### 계층 1 — 코드 절차적 애니 (무료 · 기본 · 권장)
정적 PNG 1장으로 "쥬시함"의 80%를 확보. Phaser 트윈/이징/파티클로 처리. 비용 0, 캐릭터 추가 시 자동 적용.
- 낙하 착지: 스쿼시 & 스트레치
- 합체 성공: 팝(스케일 바운스) + 파티클
- 대기: 미세 지글/호흡, 회전

```typescript
// 着地時のスクワッシュ＆ストレッチ（無料・コードのみ）
this.tweens.add({
  targets: keshi,
  scaleX: 1.15,        // 横に潰れる
  scaleY: 0.85,        // 縦に縮む
  duration: 90,
  yoyo: true,          // 元の形に戻す
  ease: 'Quad.easeOut',
});

// 合体成功時のポップ演出
this.tweens.add({
  targets: merged,
  scale: { from: 0.6, to: 1 }, // 小さく出て弾む
  duration: 180,
  ease: 'Back.easeOut',
});
```

### 계층 2 — AI 스프라이트 시트 (선택 · 유료/크레딧)
프레임 애니가 꼭 필요할 때. 참조 이미지 + 모션 프롬프트 → 투명 PNG 스프라이트 시트(프레임 수 지정, JSON 메타) 산출.
- 후보: Scenario, Ludo.ai 등 (게임용 스프라이트 시트 export)
- **주의**: 유료/크레딧. 기존 아트와 일관성 드리프트 가능 → 원본을 베이스 프레임으로 고정하고 모션만 생성 후 사람이 검수.

### 계층 3 — AI 이미지→비디오 (홍보 전용)
게임 내 X. 트레일러 · 타이틀 · 컷신용. MP4 산출이라 인게임 루프 스프라이트엔 부적합.
- 후보: Runway, Adobe Firefly, Viggle, Kling 등 (상업 안전성은 툴별 약관 확인)

### 계층 4 — 리깅 (차후 · 대개 유료)
Phase 3 도감의 풍부한 캐릭터 모션용. 레이어 분리 일러스트를 본 리깅.
- 후보: Live2D Cubism(무료판 제약 있음), Reallusion Cartoon Animator, Adobe Character Animator, Spine

### 권장 로드맵
**Phase 1 = 계층 1만으로 충분.** 계층 2는 필요한 캐릭터만. 계층 3은 홍보 시점. 계층 4는 Phase 3.

## 6. CJK 폰트 (L10N `25` 연계)
- ja / ko / zh-CN / zh-TW 자형 차이 → Noto Sans CJK 계열 또는 언어별 폰트.
- CJK 폰트는 용량이 큼(수 MB) → **서브셋(사용 글자만 추출) + 동적 로드**. 게임은 고정 문자열이 많아 서브셋 효과가 큼.
- en · 숫자는 공통 폰트.

```bash
# fonttoolsで使用文字だけを抜き出しCJKフォントを軽量化する
pip install fonttools
pyftsubset NotoSansKR.otf \
  --text-file=used_chars_ko.txt \
  --output-file=NotoSansKR.subset.woff2 \
  --flavor=woff2
```

## 7. 최적화
- **텍스처 아틀라스**: 캐릭터/UI를 스프라이트 시트로 패킹 → 드로우콜 감소(무료 패커 또는 TexturePacker 무료 기능)
- **PNG 압축**: pngquant 등으로 용량 축소
- 필요 시 해상도별 로드

## 8. 교체 / 확장 워크플로우
- 새 캐릭터: `char_<key>.png` 추가 → `merge_ladder.ts` / 도감 데이터 1줄 → 끝
- Phase 3 도감(39종) 대비, 처음부터 전체 캐릭터로 키 체계 통일

## 9. 라이선스 / IP
- 케시카스 = 자체 IP → **입력** 권리 문제 없음.
- AI 툴 사용 시 **출력물 권리 · 학습데이터 · 상업 사용 약관**을 툴별로 확인(특히 계층 2~3). 판매용은 아니나 공개 배포이므로 안전 옵션 우선.

## 10. 미해결
- 계층 2 AI 툴 무료/저비용 옵션 1종 실제 테스트 후 선정
- 폰트 서브셋 자동화(빌드 단계 통합)
- 아틀라스 패커 확정
