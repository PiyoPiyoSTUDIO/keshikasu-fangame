# 25. L10N 사양 (다국어)

- **문서 버전**: v1.1
- **최종 수정**: 2026-06-25
- **범위**: 텍스트 · 이미지 다국어 처리 전반. Phase 1부터 모든 표시 요소에 적용.

---

## 1. 목적 / 원칙
- **모든 표시 텍스트는 L10N 키로** 처리. 코드 · 이미지에 문자열 하드코딩 금지.
- **이미지**: 글자 없는 그림(캔디 · 아이스 등)은 전 언어 공통. 글자 박힌 이미지만 언어별 분기(최소화). 가능하면 글자는 폰트 렌더링으로 빼서 텍스트 L10N 하나로 해결.

## 2. 지원 언어
| 키(BCP-47) | 언어 | 비고 |
|---|---|---|
| `ja` | 日本語 | 케시카스 원본, **기본 / 폴백** |
| `en` | English | |
| `ko` | 한국어 | |
| `zh-CN` | 简体中文 | 중국 본토 |
| `zh-TW` | 繁體中文 | 타이완 |

- **폴백 체인**: 요청 언어 키 없음 → `ja`
- 키 부재 시에도 앱이 깨지지 않고 `ja` 문자열로 동작.

## 3. 키 네이밍 규칙
- 형식: `<도메인>.<요소>` — 소문자 · 점 구분
- 화면/UI: `title.start`, `game.score`, `result.retry`, `common.ok`, `common.cancel`
- 캐릭터: `char.<key>.name` (도감 대비 `char.<key>.desc`도 예약)
- 규칙: 키는 의미 기반(언어 중립). 값만 번역.

## 4. 파일 구조
```
src/locales/
  ja.json     (master = 기준 키 집합)
  en.json
  ko.json
  zh-CN.json
  zh-TW.json
```
- `ja.json`이 **키의 source of truth**. 다른 언어는 ja의 키 집합을 100% 따른다.
- 키 추가 시 ja 먼저 → 나머지 언어 채움(미번역은 ja 폴백으로 동작).

## 6. i18n 구현 (경량 · 의존성 0)
Phaser엔 i18n 내장이 없다. Phase 1은 외부 라이브러리 없이 경량 자체 구현으로 충분.

```typescript
// 軽量i18n: キーから現在言語の文字列を返す。無ければjaへフォールバック
type Dict = Record<string, string>;

let current: Dict = {};   // 現在の言語の辞書
let fallback: Dict = {};  // 常にja（フォールバック用）

// 対応ロケール一覧
const SUPPORTED = ['ja', 'en', 'ko', 'zh-CN', 'zh-TW'];

// 端末言語からロケールを推定（対応外はja）
export function detectLocale(): string {
  const lang = navigator.language;            // 例: "ko", "zh-TW"
  if (SUPPORTED.includes(lang)) return lang;
  const base = lang.split('-')[0];            // 例: "zh"
  if (base === 'zh') return 'zh-TW';          // 既定は繁体。簡体判定は別途
  return SUPPORTED.includes(base) ? base : 'ja';
}

// 辞書を登録（fallbackには常にjaを渡す）
export function setDicts(currentDict: Dict, jaDict: Dict) {
  current = currentDict;
  fallback = jaDict;
}

// キーを翻訳。無ければja、それも無ければキー文字列を返す
export function t(key: string): string {
  return current[key] ?? fallback[key] ?? key;
}
```

## 7. 언어 선택 UX
- 최초 진입: `detectLocale()`로 기기 언어 자동 감지 → 매칭 없으면 `ja`
- 설정 화면에서 수동 변경 가능
- 선택값은 localStorage(`locale` 키)에 저장 → 다음 실행 시 우선 적용

## 8. 폰트
- 한자권(ja / zh-CN / zh-TW) 자형 차이 → 언어별 웹폰트 또는 광역 폰트(Noto Sans CJK 계열).
- CJK 폰트는 용량이 큼 → **서브셋 / 동적 로드** 검토(상세 `30_에셋파이프라인`).
- en · 숫자는 공통 폰트로 처리.

## 9. 이미지 L10N
- **전 언어 공통**: 글자 없는 캐릭터 그림 `char_<key>`
- **언어별 분기(최소)**: 글자 박힌 이미지는 `<asset>__<locale>` (예: `title_logo__ko`)
- 권장: 타이틀 로고 등 "진짜 그림 글자"만 분기, 나머지는 폰트 렌더로 대체.

## 10. 번역 워크플로우
1. 신규 텍스트 → `ja.json`에 키 + 값 추가(마스터)
2. 나머지 언어 파일에 같은 키 추가 · 번역
3. 미번역은 자동으로 `ja` 폴백 → 앱은 안 깨짐
4. 미번역 키 검출: ja 키 집합과 각 언어 키 집합 diff(스크립트) — 상세 `40_QA`

## 11. 검증 룰 (중요)
- **한글-금지 룰 적용 대상**: 코드 로직 · 주석 = `*.ts` · `*.sql` · `*.yaml` · `*.sh`
- **적용 제외**: `locales/*.json`(번역 데이터). `ko.json`엔 한국어, `zh-*`엔 중국어가 들어가는 게 정상.
- 자동 검사 스크립트는 로케일 데이터 파일을 화이트리스트로 제외한다.

## 12. 미해결
- 简体(zh-CN) / 繁體(zh-TW) 자동 분기 정밀화 (navigator.language만으론 부족할 수 있음)
- **캐릭터명 중국어 검수 미완**: zh-CN/zh-TW 캐릭터 11종 이름은 Claude 초안 상태(원어민/타쿠 검수 전, 타쿠는 중국어 미독해). 특히 `char.mammoth.name` 繁體(현재 猛瑪象 vs 표준 후보 長毛象), `char.shrimp.name`(こえびちゃん의 「ちゃん」 애칭 뉘앙스), `char.seaslug.name`(海蛞蝓 학술어). 출시 전 `40` §7 L5/L6 때 일괄 검수.
- CJK 폰트 용량 최적화 방식 확정 (`30`)
- 서버 표시명(name) 문자셋 · 길이 (`50`과 연계)
- 긴 문자열(독일어 등 향후) 대비 UI 레이아웃 가변성 (`40` 테스트)
